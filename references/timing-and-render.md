# 音乐、拍点与渲染

## 测拍和剪辑决策

先找到用户选择的音乐片段。`analyze`读取指定offset之后的一段音频，使用频谱起音与自相关估计BPM，并输出网格和局部起音。它不是专业节拍标注器：弱鼓点、切分、变速、半拍/倍速都可能误判。结合原曲试听或波形检查；可用 `--bpm` 和 `--first-beat` 覆盖估计。first-beat是所分析片段内的秒数，sourceOffset=offset+first-beat，所有后续时间相对此截取点。

`beatTimes`保留稳定节拍网格；`onsetTimes`保留附近的频谱起音候选。`plan`默认整拍；确认某个起音确实是目标鼓点后可开启 `--snap-onsets`。不要把每个高频歌词音节都当鼓点；不要追逐噪声导致节奏忽快忽慢。用4拍做快速镜头、6拍作讲解、8拍留给公式/过程是可选范例，三拍子、变速或不同阅读需求应另排。

未知音乐长度时留足分析范围，使网格覆盖所有镜头及最后一个边界。输入不足报错，不能外推不存在的音乐。音乐保持原速，只对已确认的开头、结尾做短淡化与适当响度处理；不能为迁就预设3秒镜头而静默变速。

## 分镜输入与计划输出

`plan --story`使用UTF-8 JSON，例如：

```json
{
  "fps": 30,
  "scenes": [
    {"id": "hook", "beats": 4, "caption": "一个具体问题。"},
    {"id": "explain", "beats": 8, "caption": "一个核心解释。", "events": [{"id": "formula", "beat": 2}]},
    {"id": "close", "beats": 4, "caption": "回到问题，给出答案。"}
  ]
}
```

event.beat是镜头内从0开始计数的拍偏移；必须位于该镜头内部。每个镜头边界和事件都只计算一次最近帧号，`t=frame/fps`，镜头时长用相邻边界帧之差。生成的 `shots` / `cues` / `beatTimes` 供视频、字幕和音轨统一读取。sourceOffset写入FFmpeg截取参数；结束时长以最终边界帧为准。

`cueMaxRoundingErrorMs`只表示目标时间到视频帧的舍入差，不包含测拍误差、硬件播放延迟或声学不确定性。不能据此宣称实际鼓点完全零误差。

## 工程中的关键问题

- HyperFrames的根组合、clip宿主、子组合ID与 paused GSAP时间线保持一致。写工程前读取其当前组合契约，不凭记忆猜API。
- GSAP对象数值可能被保留六位小数。例如64/30=2.133333333，clock.t变成2.133333，恰好落在边界前，会造成上一镜已隐藏、下一镜还未绘制。对与最近帧仅差1e-5秒以内的值恢复为精确frame/fps；不要把所有连续预览时间粗暴取整。
- `assets/hyperframes-clock.js`提供这项恢复、paused时间线和suppressEvents下的绘制。画面回调仍须由工程实现。
- 所有画面状态只依赖当前时间，不依赖播放历史。跳播时重设可见镜头、字样、数值、颜色、透明度；隐藏镜头缓存不应影响当前镜头。不要在render里随机生成图形。
- 关键词/公式在目标帧已经可见；若前置淡入或迟0.2秒才出现，切镜落拍也不能算动效落拍。保留短暂落稳，别让阅读文字持续抖动或缩放。
- 有的渲染器seek会屏蔽GSAP onUpdate，不能只靠onUpdate绘制；渲染钩子也要能按时间绘制。不要直接把GSAP timeline作为Playwright evaluate返回值：它是thenable，暂停时可能一直等待。

## 从预览到成片

预览：音频播放器时间驱动画面seek，避免两只独立时钟累积漂移。随机跳播前后比较当前可见状态。抽查每镜、所有切点前一帧/当帧/后一帧、公式与数字变化。检查实际手机缩略尺寸；不能只在1920宽窗口读字幕。

本地：优先已可用的渲染器、浏览器和FFmpeg。Windows使用原生可执行文件，不假设bash/WSL存在。通过CLI帮助确认选项，不读取node_modules实现。避免前后台同时运行大量浏览器造成内存压力。

成片：运行 `audit_render.py`，确认规格、帧数、完整解码、有音轨；可用 `--score`核对最终配乐与封装音轨的时间偏移。对应项目配乐的crop/fade/响度修改必须发生在同步核对前。再从最终MP4提取全部切点和关键事件帧，与同帧预览核对。色彩压缩小差异可接受，文字缺失、空帧或数值晚一帧要修。

仅修一个局部问题时，修复并重新检查受影响部分即可；最终交付文件本身仍需完整解码验证。不要在没有新增改动或疑点时无限重复测试。
